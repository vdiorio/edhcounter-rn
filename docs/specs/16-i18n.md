# 16 — i18n (English + Portuguese)

## Purpose
Initialize `i18next` with `react-i18next` bindings, detect the device locale via `react-native-localize` on first launch, ship `en` and `pt` translations, and persist the user's language preference in `preferencesStore`.

## Public API

```ts
// src/features/i18n/index.ts
export function initI18n(): Promise<void>;

// src/store/preferencesStore.ts
export type PreferencesStore = {
  language: 'en' | 'pt';
  setLanguage: (lang: 'en' | 'pt') => void;
};

export const usePreferencesStore: UseBoundStore<StoreApi<PreferencesStore>>;

// Available languages constant
export const AVAILABLE_LANGUAGES: Array<{ code: 'en' | 'pt'; name: string; flag: string }>;
```

### Locale files
`src/features/i18n/locales/en.json` and `pt.json` — port the existing files verbatim. Both files share the same set of keys (~25 entries).

### Storage key
PreferencesStore is persisted under AsyncStorage key `edhcounter:preferences:v1` (separate from `gameStore`).

## Dependencies
- 01-scaffold.
- 04-persistence (uses the same AsyncStorage adapter).

## Behavior spec (TDD anchor)

### preferencesStore
1. Initial language: on first ever launch, `react-native-localize.getLocales()[0].languageCode` is read. If it equals `'pt'`, set to `'pt'`; otherwise default to `'en'`.
2. `setLanguage('pt')` updates the store AND calls `i18n.changeLanguage('pt')`.
3. Language persists across restarts via the persist middleware.

### initI18n
4. Initializes i18next with both bundled translation resources.
5. Sets the initial language from `preferencesStore` (or device-locale default).
6. Returns a Promise that resolves after i18next is ready — `App.tsx` awaits it before rendering.

### Translation usage
7. Every user-facing string in the app uses `t('key')` from `useTranslation()`. No string literals in JSX outside dev/debug paths.

## Acceptance tests
- `preferencesStore.test.ts`: behaviors 1–3, with `react-native-localize` mocked.
- `i18n.init.test.ts`: behavior 4–6.
- `translation-coverage.test.ts`: snapshot/inventory test that asserts every key in `en.json` also exists in `pt.json` (and vice versa). Fails on missing translations.

## Non-goals
- No runtime locale auto-switch on system locale change (user changes via settings UI).
- No pluralization helpers beyond i18next defaults.

## Notes for the implementer
- Port `i18n.ts`, `locales/en.json`, `locales/pt.json` from the current repo.
- Drop the `expo-localization` import and replace with `import * as RNLocalize from 'react-native-localize'`.
- `AVAILABLE_LANGUAGES` is defined inline; the flag emoji is part of the value (e.g., `'🇧🇷'`).
- Avoid loading translations from disk at runtime — `import` the JSON files so Metro bundles them.
